# Performance

The site is static HTML generated by Astro. Every page ships its content in the
markup, so the first paint does not wait for JavaScript. A single ES module adds
keyboard, explorer, finder, and in-place navigation once it loads.

## Findings

| Candidate | Evidence and affected files/routes | Decision |
| --- | --- | --- |
| Global Fira Code font | `src/layouts/Base.astro` preloads `public/fonts/FiraCode-VF.woff2` (113,088 B) across the site. The font is the dominant removable first-load resource on every route. | **Implement:** subset from generated HTML, raw Markdown, and source strings. |
| Client JavaScript and hydration | No `client:*`, `client:only`, or server islands. One shared module (`src/client/main.ts`, 90,950 B raw / 31,277 B transferred) supports keyboard controls, finder, and navigation on shell routes. | **Defer:** no oversized islands to remove; splitting or delaying the shared controls risks responsiveness without measured evidence. |
| Images and media | No large hero/LCP image. The local `MF-DOOM.png` is 7,239 B; Markdown images are lazy-loaded. Chrono includes three remote badges. | **Defer:** no high-impact local image candidate; retain offscreen lazy loading. |
| Rendering and data fetching | Astro emits static HTML: 19 pages plus fragment and raw-Markdown endpoints. There is no runtime adapter, middleware, or request-time rendering. | **Keep:** prerendering already avoids runtime rendering and preserves the build-time README snapshot behavior. |
| Build-time README snapshots | External repository README fetches dominate the roughly 9.9 s baseline build. | **Defer:** this is build-time work, not visitor latency; network variation makes a build-time optimization unproven. |
| Caching and compression | Measurements use local `astro preview`; GitHub Pages response headers were not observed. | **Investigate after deployment:** do not infer production cache or compression behavior from loopback. |

## Measured font optimization

The production build now subsets Fira Code to supported characters found in
generated HTML, raw Markdown, and source strings. It retains the variable-font
axes, glyph metrics, and outlines. Python tooling already used for the symbol
font performs the subset after Astro writes `dist/`.

The font fell from **113,088 B to 35,184 B** (−77,904 B / −68.9%). On a
cache-disabled local production preview, Lighthouse 13.5.0 was run three times
per route and device. Mobile uses Lighthouse's default mobile preset; desktop
uses `--preset=desktop`. Values below are medians; LCP ranges show all three
runs. The error-page measurements load `/404.html`; a separate check confirmed
that an unknown URL returns HTTP 404.

The exact font reduction is consistent across routes; small differences in
total transfer on `/chrono/` come from its remote resources. FCP and TTFB did
not change consistently, CLS stayed at its baseline values, and TBT remained
low with run-to-run variation. The shared JavaScript and CSS payloads and
request counts did not change. Screenshots had zero changed pixels for the
mobile homepage and desktop chrono page.

These are lab measurements, not field data. No field INP data was available;
Lighthouse TBT is not INP. Browser smoke checks exercised theme, help, finder,
focus, and client navigation without console errors or failed requests; client
navigation took about 64 ms on mobile and 61 ms on desktop. Loopback TTFB and
transfer sizes do not represent production network latency or GitHub Pages
compression.

Opening another document fetches only its rendered fragment from
`/fragments/<key>.html` (under 10 KB gzip each for the current catalog). Its Markdown loads
from `/raw/<key>.md` on demand, or on idle after a deep link. See
[README snapshots](readme-snapshots.md).

## Build-time work

Markdown parsing, sanitizing, URL rewriting, and syntax highlighting all run during
the build. The browser never downloads a Markdown renderer or highlighter.

The symbol font is subset to the glyphs the sources reference.
`src/tools/subset-symbol-font.py` scans `src/` and rewrites
`public/fonts/SymbolsNerdFont-Subset.woff2`. After Astro generates the site,
`src/tools/subset-fira-font.py` scans built and source text and replaces only
the generated Fira Code file in `dist/`. The deployment then runs
`tests/tools`, which checks glyph coverage, metrics, outlines, variable axes,
and deterministic output.

## Client runtime

Explorer listings are reused until a folder expands or collapses.

README position reports index heading ancestry for the current preview, read only
active titles, and stop measuring live positions at the first heading below the
current position, in document order. The index is rebuilt when the preview changes.
Image loading, scrolling, and resizing do not rely on cached coordinates. Unsorted
positions, such as multi-column layouts, keep the document-order behavior.

The cursor keeps its box fixed for each animation, covering the current and target
positions, and changes only `clip-path` per frame, which avoids per-frame layout.
Media outlines still size exactly per frame.

## Measuring

Install the existing font tooling, build, then preview the production output:

```powershell
python -m pip install -r .\src\tools\font-requirements.txt
npm run build
npm run preview -- --host 127.0.0.1
```

For comparable Lighthouse runs, repeat each route three times with the cache
disabled. The default is mobile; add `--preset=desktop` for desktop:

```powershell
npx --yes lighthouse@13.5.0 "http://127.0.0.1:4321/chrono/" --output=json --output-path .\chrono-mobile.json --chrome-flags "--headless --no-sandbox --disable-cache"
npx --yes lighthouse@13.5.0 "http://127.0.0.1:4321/chrono/" --output=json --output-path .\chrono-desktop.json --chrome-flags "--headless --no-sandbox --disable-cache" --preset=desktop
```

Use medians and ranges, not a single score. Local preview does not reproduce
production compression, cache headers, or network latency.
