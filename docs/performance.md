# Performance

The site is static HTML generated by Astro. Every page ships its content in the
markup, so the first paint does not wait for JavaScript. A single ES module adds
keyboard, explorer, finder, and in-place navigation once it loads.

## Payload

Measured on the production build (`npm run build`), October 2026, with offline
README fixtures. Sizes are compressed transfer sizes; GitHub Pages serves gzip.

| Resource | Raw | gzip | brotli |
| --- | ---: | ---: | ---: |
| `index.html` (CSS inlined) | 41.8 KB | 10.5 KB | 9.2 KB |
| Client JavaScript (one module) | 86.1 KB | 29.3 KB | 26.1 KB |
| `FiraCode-VF.woff2` | 110.4 KB | 110.4 KB | 110.4 KB |
| `SymbolsNerdFont-Subset.woff2` | 2.0 KB | 2.0 KB | 2.0 KB |
| `MF-DOOM.png` | 7.1 KB | 7.1 KB | 7.1 KB |
| **First load** | | **159.3 KB** | **154.8 KB** |

The previous Blazor WebAssembly build needed about 1.9 MB (brotli) before it
could render anything. Most of the remaining first load is the Fira Code font.

Opening another document fetches only its rendered fragment from
`/fragments/<key>.html` (under 10 KB gzip each for the current catalog). Its Markdown loads
from `/raw/<key>.md` on demand, or on idle after a deep link. See
[README snapshots](readme-snapshots.md).

## Build-time work

Markdown parsing, sanitizing, URL rewriting, and syntax highlighting all run during
the build. The browser never downloads a Markdown renderer or highlighter.

The symbol font is subset to the glyphs the sources reference.
`src/tools/subset-symbol-font.py` scans `src/` and rewrites
`public/fonts/SymbolsNerdFont-Subset.woff2`; the deployment runs it, then
`tests/tools` checks the shipped subset covers every referenced glyph.

## Client runtime

Explorer listings are reused until a folder expands or collapses.

README position reports index heading ancestry for the current preview, read only
active titles, and stop measuring live positions at the first heading below the
current position, in document order. The index is rebuilt when the preview changes.
Image loading, scrolling, and resizing do not rely on cached coordinates. Unsorted
positions, such as multi-column layouts, keep the document-order behavior.

The cursor keeps its box fixed for each animation, covering the current and target
positions, and changes only `clip-path` per frame, which avoids per-frame layout.
Media outlines still size exactly per frame.

## Measuring

Build, then compare compressed sizes of `dist/`:

```powershell
npm run build
npm run preview
```

Use the browser's network panel with cache disabled, or Lighthouse with mobile
throttling, against `npm run preview`. Loopback timings do not reproduce production
network latency.
