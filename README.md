# 💼 My portfolio

This repository contains the source for my personal portfolio for browsing my projects in a terminal-inspired interface. Explore the project tree, read project READMEs, search for files, or open repository links on GitHub.

The portfolio is built with **Blazor WebAssembly on .NET 10**. The interface supports mouse, touch, and Vim-style keyboard navigation. Press `?` or enter `:help` in the app for the full list of shortcuts.

The fixed root README is rendered and sanitized at build time using the same renderer as external READMEs. Its Markdown source remains available for raw view and copying. Generated HTML lives under `obj/` and is regenerated by normal builds; do not edit it directly.

External READMEs remain live: the app fetches their Markdown and downloads the renderer on first use. Markdig, HtmlSanitizer, AngleSharp, its CSS dependency, and CodePages are deferred rather than included in startup downloads. This reduces startup transfer at the cost of an extra download on the first external README. Later renders sanitize the parsed HTML in place and cache the resulting HTML for each repository and README path during the browser session. Changed Markdown replaces the cached result.

If a renderer download fails, the app displays raw Markdown and a **Reload page** recovery button. A full reload is necessary because the WebAssembly runtime can retain failed asset downloads within the current page.

`Srv.Portfolio.Content` contains shared catalog data and root Markdown, `Srv.Portfolio.Rendering` contains the lazy-loaded renderer, and `Srv.Portfolio.ContentGenerator` produces the root HTML during the build. AngleSharp's HTML encoding handler references `CodePagesEncodingProvider`; CodePages stays with the renderer rather than being removed unsafely.

Install the native WebAssembly tools before building or publishing:

```powershell
dotnet workload install wasm-tools
dotnet publish .\src\Srv.Portfolio -c Release
```

Release publishing uses native runtime relinking and managed trimming, without AOT compilation. Deployment installs the workload too.

The interface uses a subset of the bundled Nerd Font. After adding or changing icons, regenerate and verify it with Python 3.14:

```powershell
python -m pip install -r .\src\tools\font-requirements.txt
python .\src\tools\subset-symbol-font.py
python -m unittest discover -s .\tests\tools
```

Deployment regenerates the subset before publishing. Keep the original font and its license as the source for future icons.
